The most common Web Search pattern: send a query and get back a list of result URLs with metadata. This is the foundation for all other workflows in this section.

You can call Web Search in two ways:

- **[Workers Binding](/web-search/get-started/#workers-binding)**: call `env.WEBSEARCH.search()` directly from a Worker. Authentication is automatic.
- **[REST API](/web-search/get-started/#rest-api)**: send a `POST` request to `/websearch/search`. Requires an API token.

The only required parameter is `query`. Optionally pass `limit` to control how many results you get back (min 1, default 10, max 20). Each result always includes a URL and title. Other fields (description, image URL, favicon, and last-modified date) are returned when the indexed page exposes that metadata. For the full request and response schema, refer to [Get started](/web-search/get-started/#request-parameters).

<Tabs syncKey="integration">
<TabItem label="REST API">

```bash
curl -X POST \
  https://api.cloudflare.com/client/v4/accounts/{account_id}/websearch/search \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "latest Cloudflare announcements",
    "limit": 5
  }'
```

</TabItem>
<TabItem label="Workers Binding">

<TypeScriptExample>

```ts
export default {
	async fetch(request, env): Promise<Response> {
		try {
			const { items } = await env.WEBSEARCH.search({
				query: "latest Cloudflare announcements",
				limit: 5,
			});

			return Response.json(
				items.map((r) => ({
					title: r.title,
					url: r.url,
					description: r.description,
				})),
			);
		} catch (e) {
			return Response.json({ error: String(e) }, { status: 500 });
		}
	},
} satisfies ExportedHandler<Env>;
```
